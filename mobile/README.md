# Maslul (React Native)

The Maslul transit app for Israel, rewritten in React Native + Expo + TypeScript for Android and iOS. It replaces the Kotlin app in [`../app`](../app), which it was ported from screen by screen and which stays the reference for behaviour.

It keeps the Android identity, so it installs as an update over the Kotlin app:
- package `com.maslul.app`;
- versionCode 5 and up;
- on first launch it moves the old app's saved places and settings over.

License: [GNU AGPL v3](LICENSE). The data sources are credited in Settings → About, and the map credits OpenFreeMap / © OpenStreetMap contributors.

Progress, what has and hasn't been verified, and the device checklist are in [STATUS.md](STATUS.md). Design decisions are in [NOTES.md](NOTES.md).

## Setup

You need Node 20+ and npm.

```bash
cd mobile
npm ci
```

Building and running on a device also needs the platform tools:
- **Android:** JDK 17 and the Android SDK (Android Studio), or just the command-line tools. STATUS.md (Phase B) lists the SDK packages and the hosts Gradle downloads from.
- **iOS:** a Mac with Xcode and CocoaPods.

The app has its own native module (`modules/maslul-native`), so it can't run in Expo Go. It runs as a development build.

## Scripts

| Command | What it does |
|---|---|
| `npm test` | Offline Jest suites: the ported Kotlin unit tests, the migration, the parsers on recorded fixtures, and screen flows with the native parts mocked |
| `npm run test:live` | Smoke tests against the real services: Transitous, Stride, SIRI snapshots, Photon and Nominatim. `RECORD=1` refreshes `fixtures/` |
| `npm run typecheck` | Strict `tsc` |
| `npm run prebuild` | Generates `android/` and `ios/` from `app.config.ts` (git-ignored, recreated on every build) |
| `npm run android` / `npm run ios` | Builds a debug app and installs it on a connected device or emulator |
| `npm start` | Metro for an installed development build |
| `maestro test .maestro/` | Device flows mirroring the Kotlin app's AppFlowTest (needs [Maestro](https://maestro.dev) and the app installed) |

## Release builds

Bump the version in **`version.json`**, the single place to change it. `versionCode` doubles as the iOS build number.

**Android:** release signing reads the same `keystore.properties` as the Kotlin app, from the repository root. It is git-ignored and never committed. Its paths resolve the same way they did for the Kotlin build. The `plugins/withReleaseSigning.js` config plugin wires it into the generated Gradle project.

```bash
npm run prebuild
cd android && ./gradlew assembleRelease   # or bundleRelease for an .aab
```

Without `keystore.properties` the release build falls back to debug signing.

**iOS:** `npm run prebuild`, then open `ios/Maslul.xcworkspace` in Xcode and archive with your own team.

## Layout

```
app.config.ts         Expo config: ids, permissions, plugins (native projects are generated from it)
version.json          version and versionCode
index.ts              entry: registers the background location task, then the app
src/
  data/               the Kotlin data layer ported file for file: APIs, models, ranking, ETA, rides, shuttles…
  state/              user store and its migration, location, the shared repository instance
  live/               live directions (foreground location service), trip guide, notifications
  ui/                 theme, navigation, components, the map, and screens/
  native.ts           JS side of the native module
modules/maslul-native Kotlin + Swift: old-store read, SIRI brotli decode and parse, trip notification
plugins/              config plugin for release signing
assets/               icons, splash and map sprites (generated by scripts/make-assets.mjs from ../app's drawables)
__tests__/            Jest: unit, screen flows (support/fakeRepo.ts) and live/ smoke tests
fixtures/             real service responses (with the URL each came from) for offline tests
.maestro/             device flows
```
